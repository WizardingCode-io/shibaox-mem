# ADR 0002 — M1: core and Claude Code in local mode

Date: 2026-10-05 · Status: accepted on macOS arm64. Linux and Windows remain to be validated (the CI has never run).

## What exists

One binary with the commands `hook`, `distill`, `mcp`, `install`, `uninstall`, `doctor` and `status`. It captures turns through Claude Code's four hooks, distils them into memories without any generative model (heuristic judge), injects a summary at session start and the relevant notes on each prompt, and exposes `memory_search`, `memory_get` and `memory_save` over MCP.

## Measurements

Compiled binary, macOS 26 arm64, Bun 1.4.2.

| What | Result |
|---|---|
| Suite | 641 tests, including those that compile and run the binary |
| Prompt hook with 5,000 memories | p95 ≈ 25 ms (budget: 80 ms) |
| Session-start hook with 5,000 memories | p95 ≈ 20 ms (budget: 150 ms) |
| Turn-end hook | p95 ≈ 16 ms (budget: 60 ms) |
| Hostile 320 KB prompt (hex) | under 1.5 s end to end; before the fix, over 20 s |
| Real sessions in Claude Code 2.1.289 | hooks ≤ 17 ms, 0 errors, 0 resident processes, 0 model calls made by shibaox-mem |
| Retrieval, golden set | recall 19/24, precision 19/21, false injections 0/23 |
| Heuristic judge filter, golden set | precision 16/16, recall 16/16 |

**The golden sets were written by hand by the author of the rules.** They are a regression baseline. They do not measure how the system behaves in real projects: the independent review found 14 mundane prompts that the judge kept as conventions despite the 16/16, and that is what led to the current "standing instruction" rule.

The five recall misses are paraphrases with no words in common with the memory. Lexical search does not find them; that is the use case for the TypeSafe judge (M2) or for vectors.

## Decisions that depart from the plan

**Capture**
- The turn is identified by (`session_id`, `prompt_id`). It opens at the prompt; `SessionEnd` closes whatever was left open; a turn open for more than 12 h is given up as abandoned at the start of the next session.
- A turn can end more than once (another `Stop` hook tells the agent to continue). The last ending stands, and re-distilling a turn updates its single memory.
- One memory per turn.

**Distillation**
- The memory body is the selected facts plus a `Context:` line with the request, when the title comes from the assistant's reply.
- A sentence from the prompt only counts as a rule if it is not a question, a request or bound to the moment, and if the cue is not a mere observation.
- What the agent repeats from the notes it was shown is removed before judging the turn (exact textual match).
- A turn in which the agent successfully called `memory_save` is not distilled.
- Consolidation checks "supersedes" before "duplicate".

**Retrieval**
- No reranking and no internal deadline (`Deadline`): the judge is local and synchronous. Both are left for M2.
- Light stemming (PT and EN plurals, `-ed`/`-ing` in EN), stored in the `terms` column and added to the query. It raised recall from 14/24 to 19/24.
- The evidence to inject is weighted: generic programming word 0.5; normal word 1; rare word 1.5; 3 are needed, or a specific identifier, or a file touched in the session plus one non-generic word. "Rare" is relative to the project's size, never below one memory.
- The startup summary shows only titles. A note named in the summary can still be shown in full, once, when a prompt makes it relevant.
- Joins with the full-text index use `CROSS JOIN`: SQLite's planner was inverting them (90 ms per word with 5,000 memories).
- Staleness only detects files that have disappeared.

**Installation**
- Hooks in exec form (`command` + `args`) with an absolute path; the MCP server is registered with `claude mcp add`.
- The receipt and the backup are per settings file and are only valid while the file is as we left it. Otherwise `uninstall` removes our entries and keeps the rest.

**Schema**
- Migration `0001` was edited after being written (the unique index on `injections` now includes `event`). No version has been published, so there are no databases to migrate. **From the first release on, a change is always a new migration.**

## Left to do before moving on

1. ~~Pre-migration backup outside the lock~~ — fixed on 2026-10-05: a second connection takes the write lock before the backup and holds it until the migrations finish; only one process performs the upgrade.
2. **Staleness and branches:** a note anchored to a file that only exists on another branch is marked as out of date until that branch is checked out again.
3. **Old hosts:** with no arguments, the binary prints the help even with a payload on stdin. In a Claude Code that ignored `args`, that would be injected as context. The exec form was verified on version 2.1.289; it is not known from which version it exists.
4. ~~**Echo over MCP:** what the agent reads with `memory_get` and repeats is not filtered, because the MCP server does not know the session.~~ Resolved in M3: the server knows the project and the moment; a call happens inside a turn, so the read is recorded (`injections.event = 'mcp'`) against the project's sessions with a turn open at that instant, and the echo is filtered like that of injected notes.
5. **Test of `distill` killed midway:** it simulates the state via SQL instead of killing a process.
6. **Windows:** known POSIX assumptions — 0600/0700 permissions with no effect; `rename` over a `.exe` or a `settings.json` in use; `claude.cmd` not resolved without a shell; CRLF line endings converted; case-sensitive path comparison; `pgrep` and URL paths in the tests.
7. **Secret redaction:** it is rule-based and fallible. An adversarial review found 22 forms out of 29 that got through; the most common were closed, others will exist.
